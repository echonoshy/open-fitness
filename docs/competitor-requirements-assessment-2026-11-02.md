**Viaim Coach 同类产品调研与需求评估**

调研日期：2026-11-02。阶段：需求评估，未进入实现。

本次按当前产品的 macOS、单人、普通摄像头与中文语音定位评估，以居家基础训练为主要假设，办公短时活动作为待验证场景。竞品依据来自本次检索的官方产品页、帮助文档及历史公司披露；没有实际购买、登录体验或独立验证其识别精度、效果和留存。优先级、成本和建议验收指标是本次产品判断，不是竞品公开数据。

**3. 建议需求清单与优先级**

P0 表示扩大功能前的必要基础；P1 是下一轮最值得验证的用户价值；P2 是在第一轮证据成立后推进。成本只表示相对量级，包含实现、内容与真人验证，不是排期承诺。

| 优先级 | 需求 | 相对现状的具体增量 | 用户价值 | 相对投入与主要难点 |
| --- | --- | --- | --- | --- |
| P0 | 首次完成一组的可靠性 | 统一准备、识别中、可计次、仅局部可评估等状态；测量设备就绪至有效训练的耗时与卡点 | 用户明白为什么没计数、下一步该做什么 | 界面低至中，真人验证高；优先找真实阻塞点，不能先假定仍有旧缺陷 |
| P1 | 按时间和场景选择今日训练 | 在现有计划上提供少量 10/15/20 分钟模板，按器械、场地、站立/地面条件筛选；时长包含休息和转换 | 从“我应该练什么”直接到可开始的训练 | 软件中、内容中；首期选 3 套模板即可，具体时长需实测 |
| P1 | 纠错后的改善确认 | 对一个已提示问题持续观察，足够有效重复后确认改善；不把遮挡或丢点当改正 | 用户知道自己有没有听懂、有没有做对 | 软件中、识别验证高；需要问题持续性、有效样本、视角和置信度条件 |
| P1 | 训练结果接到下次行动 | 在现有总结上补一个有依据的进步点、一个优先练习点，以及“沿用/缩短/调整下次计划”的入口 | 训练记录直接帮助下一次训练 | 软件中、规则中；只比较相同动作、相近负重和可比较视角，缺证据就不推断 |
| P2 | 训练感受与渐进调整 | 记录“轻松/合适/吃力”和主动反馈的不适；把实际完成情况用于下一次建议 | 教练逐渐适应个人，不总是重复同一安排 | 软件中、规则和专业审核中至高；推荐与执行分开，变化可查看和撤回 |
| P2 | 单动作学练 | 示范→低压力试做→只关注一个可检测问题→再做验证→小结 | 降低新手理解成本，发挥已有参考视频价值 | 软件中、内容中、真人验证高；每个动作先覆盖 1—2 个问题 |
| P2 | 周目标与阶段复测 | 简单周目标、固定练习的前后对比、用户自愿开启的提醒 | 让用户看到持续变化，形成回访理由 | 软件中；已有趋势和连续天数可复用，需更长使用周期验证 |

其中“短时训练入口”和“单动作学练”可以共用课程组织，但要分别验证：前者解决启动和完成问题，后者解决理解和纠错问题。不要把二者一次打包成内容平台。

**4. 三项优先需求的最小范围**

**今日训练入口：先提供可解释、可完成的选择。**

用户场景：“我只有 10 分钟，没有器械，今天不方便趴地。”

产品应读取当天条件，给出一份可预览的短计划，并允许替换动作、缩短或开始。用户不必自己填写全部组数和休息时间。先从现有已验收动作与审核过的模板中选择；如果组合不能满足条件，应明确说明限制。热身和整理活动可以先采用示范与计时，必须与摄像头可评估动作区分。

“10 分钟”应是包含准备、动作切换和休息的合理估计，不保证每个人恰好 10 分钟。需要让用户知道预计结束时间，并在时间不足时提供保留目标的缩短方案。

首期不依赖完整周历、外部健康平台或无限制生成动作。

**改善确认：让一次提示有后续。**

一次理想体验是：发现可观察问题 → 给一句具体提示 → 后续动作继续观察 → 确认改善，或在休息时给更容易理解的示范。

例如，在具备可靠节奏测量的动作里提示“下一次下放慢一点”，后续有效重复支持时再反馈“后面几次下放更稳定了”。该例是交互示意，不是对当前训练结果的陈述。

新增重点是记录“提示了什么、之后有没有改变”。当前已具备纠错节流、优先级和鼓励，因此不需重新发明这些机制。每次只聚焦一个重要问题；视角变化、人体遮挡或证据不足时，暂停改善判断。持续重复后仍未改善，可以在休息中给示范，不提高播报频率。个人基线也不能把原本存在的问题自动认定为标准动作。

**下次建议：用可核对的事实推动下一步。**

当前已有组次总结和下一组注意事项。增量是训练结束后，把可比较的证据与下一次计划连接起来。

总结建议限制为三件事：完成了什么；哪一项有依据地改善或仍需留意；下次建议延续哪套计划、聚焦哪个点。用户可以沿用、修改或忽略。起步时优先沿用熟悉计划和练习重点；增加次数/重量需要更多完成情况与主观感受依据。

不能把局部评分变化、不同镜头角度、不同负重或缺失样本混成一个“整体变强”结论。长期趋势比较还需考虑规则版本变化。

**5. 暂缓的功能**

| 功能 | 当前暂缓理由 | 重新评估条件 |
| --- | --- | --- |
| 上百个可识别动作 | 每增加动作都增加识别、视角、示范、规则和测试负担 | 先证明现有核心动作的计次与纠错可靠，并确认用户反复请求的动作缺口 |
| 多人同练、排行榜、体感游戏 | 当前训练状态与识别围绕单人；这些功能增加身份归属和使用场景复杂度 | 用户研究显示家庭多人/娱乐是主要使用理由 |
| 康复方案、疼痛诊断、体态疾病判断 | 进入不同的专业责任、证据与产品定位 | 有明确业务方向、专业合作及单独的验证方案 |
| 摄像头体脂扫描、精确热量、精确恢复分数 | 现有设备与数据不足以支撑可信的精确表述 | 确认测量来源、精度边界和用户决策价值 |
| Apple Health/手表等外部连接 | 有价值，但增加跨设备与同步成本，目前不是完成一次训练的必要条件 | 用户确有相关设备，且外部数据能改变具体建议 |
| 大型直播课与社区 | 内容持续制作和运营成本高 | 证明课程内容或教练关系是主要留存原因 |
| 自动记录/回放每次训练视频 | 可帮助复盘，但引入存储、选择片段和隐私体验成本 | 先验证用户是否会使用回放，以及什么片段最有帮助 |

**6. 编码前的验证建议**

先找 6—8 位目标用户：包含训练新手、已有简单训练习惯的人，以及少量办公短时活动用户。这个样本用于发现使用障碍和比较方向，不用于推断整个市场或证明统计显著性。

第一轮安排三件事：

1. 使用当前产品独立完成一段 10—15 分钟训练，观察从选计划到保存结果的全过程；记录摄像头准备耗时、人工帮助次数、误计漏计、暂停原因和是否完成。
2. 用纸面或静态流程比较“自行配置计划”与“按时长/条件选模板”，看用户是否更容易选到愿意开始的训练，是否理解动作和器械要求。
3. 在同一动作练习中，由研究人员根据经核对的实际表现提供“纠错后改善确认”和三句式训练小结。明确这是人工辅助实验，用于测试内容与时机是否有用，不验证自动算法能力。

建议的初始通过条件如下，均需结合第一轮基线修订：

| 验证对象 | 初始判断标准 |
| --- | --- |
| 启动体验 | 设备已授权且可用后，多数用户能在约 2 分钟内开始有效训练；每次超时都能定位原因 |
| 模板价值 | 多数用户能自行选定合适计划，且未出现不符合器械/场地限制的推荐；比较两种入口的耗时和犹豫点 |
| 改善反馈价值 | 用户理解提示、能指出如何改变动作，且不会因播报明显打断动作 |
| 改善识别可行性 | 在单独的真人标注素材上区分确实改善、未改善与不可评估；初始目标可设改善提示精确率 ≥90%，同时报告覆盖率和样本量，不能靠几乎不提示达标 |
| 总结可信度 | 提及的数字和变化均能回溯训练记录；样本不足时明确不比较；用户能复述下次练习重点 |
| 回访价值 | 两周内观察是否主动再次训练、是否使用上次建议，记录未回访原因；不把口头“愿意用”当留存 |

识别验证应覆盖体型、衣着、光照、距离、镜头角度和遮挡，避免同一人的同一段视频同时作为调参与最终验收依据。对用户不适或要求停止的表达，应沿用现有停止/暂停边界，不让实验反馈推动其继续挑战。

**7. 本次建议的下一版范围**

建议保留一个清晰的训练主流程：选择适合今天的短计划 → 摄像头就位 → 示范与练习 → 一次只处理一个问题 → 休息与下一组 → 有依据的小结 → 下次继续。

如果只能投入三项，选择：**少量短时训练模板、纠错后的改善确认、训练总结到下次计划的连接**。首次训练可靠性作为三项共同的验收前提。办公场景的站立活动、周计划、外部设备与新动作，应根据第一轮真实使用结果再决定是否扩展。

商业价值仍是待验证假设：用户是否愿意反复打开电脑、为可信的动作反馈付出时间或费用，以及房间摆位成本是否抵消便利。竞品拥有某功能只能证明参考路径存在，不能替代这些需求证据。
