# 主动语音交互设计

日期：2026-10-23。适用版本：0.3.6。对象是在 Mac 上连接 viaim Connect、边训练边听教练的试用用户；本轮聚焦一次训练内的陪伴、引导与打断，不新增运动处方或改变计数算法。

等待反馈设计与当时的验证结果见 [语音等待反馈验证](https://github.com/echonoshy/open-fitness/blob/fb1e8ddef152d6b20c97e6638f4dbd9be83832b0/docs/voice-waiting-feedback-validation-20261027.md)。

## 同类产品的证据与取舍

以下来自产品官方公开资料，未实际操作这些设备，也不把营销说明视为准确率验证。

| 产品 | 可核对的做法 | 对本项目的启发 |
| --- | --- | --- |
| [Tonal](https://tonal.com/blogs/all/tonal-quick-start-guide) | 根据传感器观测给出具体纠错；支持实时查看及训练后回看提示。 | 提示应对应当前可观测的问题，不能泛泛地不停鼓励。 |
| [Tempo](https://support.tempo.fit/support/solutions/articles/151000154714-3d-tempo-vision-form-feedback) | 解释了为何不每次错误都提示，避免挫败感；也反馈动作得到纠正。 | 需要稳定触发、重复间隔，以及承认改善的能力。当前未充分验证“已纠正”的独立证据，因此这次不贸然加入动作已标准的表扬。 |
| [Ray](https://www.rayfit.com/blog/2026/02/what-is-ai-personal-training/) | 对话结合历史与偏好，用户可要求多一点或少一点指导；明确区分摄像头计次与判断动作正确。 | 让用户控制提醒强度；计数成功只说明进度，不证明姿势正确。 |
| [Apple Fitness+](https://support.apple.com/guide/fitness-plus/customize-experience-a-workout-meditation-apd12f665e17/ios) | 用户可调整教练/音乐侧重、额外语音提示及提示速度。它主要是课程引导，非本项目的实时视觉判断。 | 语音密度是一项用户偏好，而非越多越好。 |

推导出的方案：本地状态决定时机，模型负责自然表达；优先解决用户眼下需要知道的事。下文所有具体间隔是本产品的保守试用参数，不是竞品公开标准或已经验证的最佳值。

## 一次训练中的节奏

| 场景 | 默认行为 | 保持安静的条件 |
| --- | --- | --- |
| 进入训练 | 数据加载、收音就绪后，约两秒起尝试一次问候。有实际训练记录才说“欢迎回来”。 | 正在说话、关闭语音、离开训练页；不反复问候。 |
| 开始一组 | 说明真实动作和目标。 | 用户刚通过语音发起的操作已有结果收据，避免重复播报。 |
| 尚未站好、跟踪丢失 | 问题持续约 2.5 秒才提示位置；使用本地实际提示。 | 瞬时遮挡、已经恢复、关闭动作纠错提示。 |
| 动作问题 | 当前同一问题持续 1.5 秒后，从严重问题中选一个提示。 | 瞬时变化；同一问题 25 秒内不重复。 |
| 组内进度 | 适中模式最多两次：约半程与目标前两次，最早不早于第 4 次；例如 12 次目标在 6 次、10 次时尝试提醒。 | 用户说话、姿态不可用、有动作问题、刚说过话；次数已变化则不追补。 |
| 平板支撑 | 使用本地有效支撑累计值，在半程及目标前五秒尝试提示。 | 不把墙钟时长当成有效支撑；过时则跳过。 |
| 组间休息 | 观察到至少 25 秒的休息时，在余下约 10 秒给一次准备提示；结束时提醒当前动作。 | 很短的休息不额外倒数；过期提示丢弃。 |
| 达标与结束 | 自由训练达标只提示，不自动停止；计划转换和结束依实际状态播报。保存后才能说已保存。 | 正在回答用户时不抢话，旧阶段的提醒不带到下一阶段。 |
| 用户开口 | 立即取消主动文字生成、合成及播放，接收新请求。 | 不恢复被打断的鼓励；正式回答结束后至少留 8 秒安静期。 |

普通主动播报默认至少间隔 14 秒，积极模式至少 9 秒；纠错/站位提示至少间隔 8 秒，达标/结束至少 5 秒。这里只是允许开始的最小间隔，实际还受播放完成、有效期和用户优先规则约束。不会每隔固定秒数强行说一句。

“安静”保留阶段与动作问题提示，关闭中途进度；“适中”每组最多两次进度；“积极”最多三次，仍遵守冷却和打断。设置在“设置 → 教练声音”，也可说“少说一点”“多鼓励我”“恢复适中提醒”。用户主动提问不受该频率限制。

## 模型负责什么

等待表达优先使用现有 Responses API 同一轮决策请求中的自然开场。“我查一下”“我想一下”等简短意图可以通过校验，短逗号分句也可以提前播出；查询结果、已完成操作、未经确认的数字仍不能混入开场。模型请求的参数、工具决策、调用顺序和最终回答路径不因反馈开关而改变。短命令仍可直接执行并返回真实结果。

首轮若只说话不调用工具，应用强制补回原有工具决策；后续查询、复合操作和最终回答流程保留。工具完成前只允许简短意图播报，不能读未经核对的结果。意图、操作收据、正式答案分别管理，意图不算回答，不能吞掉最后答案。

识别完成并开始处理后750毫秒仍没有回答、操作收据或模型开场时，按本轮问题、明确的时间/动作范围、上一轮简短追问的主题及已经开始的查询，选择一次简短意图回应。表达只用于反馈，不决定工具或替代查询；近期实际播出的表达会被避开，不按固定间隔反复播报。查询状态同时参与语音反馈，快速查询不额外插话。

模型自然开场可替换尚未出声的上下文兜底；相同文本升级为真实查询进度时复用已在进行的合成。已出声的等待语每轮最多一次。正式答案和操作收据到达后取消未出声的等待语，已经开始的短句与答案使用同一个播放队列顺接；用户开口则取消合成与播放，丢弃过期音频。反馈合成失败不妨碍最终答案。诊断新增`coach_waiting_queued`，记录来源和耗时，不记录原始用户文本；`coach_waiting_audio`仍代表首段PCM到达，不能当作扬声器实际出声时间。

主动鼓励使用单独的只读短请求，只提供事件类型及近期表达；它没有任何操作工具，也不决定次数、目标、是否完成或何时休息。具体数字、单位与保存结果由本地状态直接组成事实句，模型只补一句陪伴的话。重复数字、动作正确性判断、未执行操作声明及具体身体动作建议会被过滤；不合格时只读事实。

主动表达生成最多等三秒，失败后一分钟内使用简短事实，避免连续请求故障服务。每条提示在生成结束、首段音频到达及状态变化时再次检查有效性。待播数字最多保留四秒，并要求次数未变；正在播放时不因下一次计数而把句子切碎，但用户开口、切换阶段或跟踪失效仍会取消。

## 试用时重点观察

自动化已覆盖规则与取消；真实服务测试只使用合成请求和内存训练数据。还需要真人训练判断：提醒是否刚好、说话是否自然、旁人/音乐是否触发误打断，以及扬声器远场双讲效果。不能用浏览器模拟和打包成功替代这些体验结论。

后续应依据真实反馈调整频率，而非继续增加鼓励数量。优先记录提示触发的阶段、是否被打断或因过期丢弃；不靠收集摄像头视频来调提示节奏。
