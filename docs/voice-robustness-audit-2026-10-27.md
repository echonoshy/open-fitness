# 语音交互鲁棒性检视

更新：本报告保留修复前的检视证据。F1–F7已在工作区修复，修复后的行为、真实模型复测结果及现场验证边界见[修复与验证报告](voice-robustness-fix-validation-2026-10-27.md)。

日期：2026-10-27。对象：当前工作区0.3.13源码及桌面端已保存的服务配置。目的：核对现有能力、同义表达、否定与作用对象、工具执行和打断边界。此次未修改应用实现，仅新增隔离检查脚本、结果和本报告。

主要结论：常见自然语言操作大多能正确选择工具，但存在6类需要优先处理的问题，以及1个较轻的状态回执问题。问题集中在本地路由与模型之间的能力缺口、过宽的拦截规则、最终答案合并和异步取消。没有证据支持把所有语句都改为宽泛的关键词执行。

## 验证范围

- 77个语义用例，其中70个实际调用当前配置的 `deepseek-v4.1-flash` 服务，另7个走本地快捷路径；共145次模型请求。本批次无服务错误，但“请求成功”不等于行为正确。
- 用例覆盖全部21个工具的至少一个调用路径；不代表每个参数组合、每种训练状态和所有说法都已穷尽。
- 训练状态、历史和用户资料均为内存中的合成样本。没有操作用户正在使用的训练会话，没有写入用户训练记录或个人资料。
- 6条合成语音通过当前TTS→ASR服务核对，转写保留了“停”“停下来”“不做了”“别停”“停止说话”“不休息了，继续练”的核心词及否定。
- 本地确定性探针覆盖回复拦截、否定/假设语句、模型不可用、取消期间的摄像头启动、休息状态回执。
- 摄像头启动取消问题使用从当前 `App.tsx` 提取的原始 `dispatch`、`cancel` 函数体执行，只替换React设置器、持久化和真实摄像头为内存桩。
- 未做真人麦克风、扬声器回声、音乐/旁人干扰、远场收音或完整现场训练测试。

## 确认的问题与修正边界

### F1：正确的状态回答被“虚假执行”拦截（P1）

真实模型返回的答案是正确的，但应用过滤掉了答案：

| 问题 | 模型原始答案节选 | 最终显示/播报 |
| --- | --- | --- |
| 我现在做了几次？ | 你已完成6次，目标12次，还差6次。 | 这次没有执行任何操作。请具体说明想调整什么，也可以询问当前训练状态。 |
| 训练已经开始了吗？ | 已经开始了，深蹲进行中，目前完成6次…… | 同上 |
| 我已经完成几次了？ | 这组深蹲已完成6次…… | 同上 |
| 当前摄像头已经开启了吗？ | 摄像头已开启…… | 同上 |

原因：`falseExecution` 只要匹配“已完成、已开始、已开启”等字样，就标记为 `unconfirmed_execution`，没有区分状态陈述和“本轮执行了操作”的声明。流式回答阶段据此整句丢弃，并触发操作失败兜底。

位置：`desktop/src/core/diagnostics.ts:39`、`desktop/src/core/coach.ts:176`。

建议：分别校验“当前事实”和“本轮操作结果”。有状态快照支持的“已经完成6次”应正常输出；声称“我刚把目标改成15次”则必须有对应成功回执。不能简单移除所有执行校验。

证据：`live-other.json` index 5–8，`edge-probes.json` 的 `truthful_current_state_rejected`。

### F2：健康关键词规则误执行暂停，否定/假设/第三人语句也触发（P1）

以下语句在不经过模型的情况下直接暂停了正在进行的训练：

- “我没有受伤，可以继续训练吗？”
- “胸痛是什么意思？”
- “如果出现胸痛应该怎么办？”
- “我朋友说他呼吸困难”
- “如果受伤了还能继续练吗？”

原因：紧急关键词分支只检查关键词前很短的否定前缀；“受伤……继续”等另一分支没有否定处理。两者都没有区分当前本人症状、假设、解释和第三人叙述。匹配后 `coachTurn` 立即派发 `session.pause`。

位置：`desktop/src/core/knowledge.ts:258`、`desktop/src/core/coach.ts:107`。

建议：保留明确当前本人不适时的及时处理，对否定、假设、引述和知识咨询做语义区分。不要继续增加会覆盖更多正常问题的宽泛关键词组合。这里只评价应用的意图识别，不评价医学建议。

额外发现：该分支位于取消检查之前，给已取消的turn传入同类语句仍会派发暂停；建议与F6一起统一取消边界。

证据：`offline.json` 的 `safety_scope`，`edge-probes.json` 的 `cancelled_turn_safety_still_mutates`。

### F3：减少提醒、停止说话、关闭纠错被混为一谈（P1）

- “少说一点”命中本地规则，正常进入安静模式。
- “请少说一点”没有命中规则。模型回复“好，之后简短说”，但没有修改提醒设置。
- “不要一直鼓励我”回复“之后只报数据和动作问题”，但主动陪练设置没有修改。
- “提醒少一点”实际调用 `cues(false)`，关闭了动作纠错，其他阶段/进度播报仍可继续。
- “停止说话”“我不是说停止训练，我是让你停止说话”“请不要暂停，也不要结束，我只是想让你安静一会儿”均实际调用了 `cues(false)`。

原因：提醒密度只有本地精确短语入口，模型没有相应工具；模型可见的 `cues` 实际控制纠错与站位提示，因此它被拿来代替不具备的能力。主动陪练模型不读取这轮用户的“少鼓励我”承诺，不能靠会话回答让设置生效。

位置：`desktop/src/core/interaction.ts:11`、`desktop/src/App.tsx:651`、`desktop/src/core/coach.ts:21`。

建议：明确分开“停止本次播报”“调整主动提醒密度”“关闭动作纠错”“关闭全部播报”，给确实需要通过自然语言控制的能力提供准确入口。至少覆盖礼貌前缀和合理同义表达；不要把所有“安静/别说”都映射成关闭纠错。

证据：`live-stop.json` index 17–18，`live-other.json` index 0–4，`live-extra.json` index 18–19。

### F4：复合请求完成操作后，应用丢失模型的回答部分（P1）

| 输入 | 已完成内容 | 丢失的回答 |
| --- | --- | --- |
| 帮我暂停训练，然后告诉我现在做了几次 | 暂停成功 | 模型已经回答的6次 |
| 把这组目标改成十五次，再告诉我还差几次 | 目标修改成功 | 模型已经回答的还差9次 |
| 暂停训练，查一下上周深蹲的平均得分 | 暂停和历史查询都执行 | 模型已经回答的95分；最终仅剩组数、次数摘要 |
| 请暂停，然后告诉我杠铃六十公斤怎么配片 | 暂停和配片计算都执行 | 模型已经回答的每侧20公斤 |

原因：工具循环拿到最终文字后，只要此前存在操作回执，就在 `coach.ts:305` 直接返回回执拼接，丢弃模型文字。`history_query` 只有固定组数/次数摘要，`plate_calc` 没有补充摘要。失败回执也会进入同一集合。

位置：`desktop/src/core/coach.ts:165`、`:304`、`:365`、`:396`。

建议：保留经过校验的最终回答，并与成功/失败回执去重合并。回执用于证明操作结果，不能替代用户另外提出的问题；不能为解决此问题取消最终答案校验。

证据：`live-extra.json` index 0–3，`edge-probes.json` 的 `compound_answer_lost_when_any_action`。

### F5：常用停止表达在LLM不可用时无法执行（P1）

在相同的进行中状态，注入LLM不可用错误：

| 输入 | 模型请求数 | 结果 |
| --- | --- | --- |
| 暂停 | 0 | 正常暂停 |
| 停止 | 1 | 请求错误，训练状态仍为training |
| 停下来 | 1 | 请求错误，训练状态仍为training |
| 不做了 | 1 | 请求错误，训练状态仍为training |

正常在线时，这些表达在本次样本中能够执行；因此不能称为“不支持同义词”。问题是最常用的停止意图缺少与已有“暂停”同等的本地可靠路径。

位置：`desktop/src/core/voice-routing.ts:173`、`desktop/src/core/coach.ts:123`。

建议：为完整、明确的停止/暂停/结束表达提供稳健的本地处理，或在模型失败时提供等价兜底。限定完整语句和作用对象，并保留对否定、引用、条件、未来、复合请求的区分；不能使用“包含停字就暂停”的规则。此措施仍依赖ASR得到正确文字，不能称为离线语音。

另外应统一产品语义：本次“停止”结束训练，“停下来”暂停。建议短促、不明确的停止先暂停并保留会话；明确“不做了/今天结束/结束并保存”再结束。此为建议的交互约定，现有记录本身不证明“停止”只能有唯一解释。

证据：`live-stop.json` index 0–8，`edge-probes.json` 的 `llm_unavailable_stop`。

### F6：开启摄像头期间取消当前语音轮次，旧的开始操作仍会执行（P1）

用当前应用原始函数体重现的时序：

1. 摄像头未就绪，派发 `session.start`，等待 `startCamera()`。
2. 调用应用实际的 `cancel()`，本轮请求已abort，turn ID递增；训练仍为ready。
3. 令摄像头就绪。
4. 旧的 `dispatch` 继续执行，训练变为training，并返回开始准备检查的成功回执。

原因：取消语音只改变turn ID和AbortController。等待摄像头的启动路径检查 `startRequest`，却不检查语音轮次/取消信号；`cancel()` 也不改变该启动标识。之后真正执行了暂停/结束/关闭摄像头的命令才会使 `startRequest` 失效，单纯打断或“先别开始”的无操作回答不一定会。

位置：`desktop/src/App.tsx:248`、`:542`。

建议：让语音派发携带所属turn或AbortSignal，在异步等待结束、准备产生副作用前再检查有效性。区分“已经完成的操作不撤销”和“尚未执行的旧操作必须取消”，并保留界面按钮自己的启动流程。

证据：`edge-probes.json` 的 `cancel_during_camera_start`。这是隔离状态机重现，未在真实摄像头设备上复测。

### F7：不在休息时仍返回“休息已结束”（P3）

在ready、正常training、paused状态直接调用 `session.cancel_rest`，均返回成功及“休息已结束”，即使没有休息倒计时；paused状态也仍然保持paused。

位置：`desktop/src/core/session.ts:553`。

建议：给出与当前状态相符的回执，例如“当前没有休息倒计时”；如果用户其实要恢复暂停中的训练，应交给resume意图处理。

证据：`offline.json` 的 `cancel_rest_states`。

## 建议的处理顺序和验收原则

先修正确定性误处理：F1状态回答误拦、F2否定/假设误暂停、F4答案丢失、F6旧操作未取消。随后补齐F3准确的语音控制入口和F5停止语义的可靠路径。F7可一并修正。

每个正向用例都配一个意义相近的反向用例：暂停/别暂停、停下来/这是台词“停下来”、停止训练/停止说话、减少鼓励/保留纠错、修改本组目标/另开一组。避免通过简单扩大关键词匹配修复一类问题，却制造另一类误操作。

执行验收必须同时看实际状态和最终答案：既验证“真的暂停了”，也验证“用户问的次数或查询结果仍有回答”。取消验收应在不同异步边界注入打断，而不仅测试模型返回之前取消。
