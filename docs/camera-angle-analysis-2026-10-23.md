# 动作示意图复核与拍摄角度分析

日期：2026-10-23。范围：修正当前训练面板的 9 个动作示意图，分析拍摄引导和多角度识别。此次不改变识别、计数、计时或纠错规则。

## 1. 示意图复核

图形表示动作姿态或准备姿态，不是完整动作教学。重点核对肢体方向、关节连接、支撑面和器械关系。

| 动作 | 复核结果与处理 | 当前推荐拍摄方向 |
| --- | --- | --- |
| 深蹲 | 保留侧身站直的准备姿态，与现有站位检查一致；不是最低点示范 | 侧面，肩、髋、膝、踝入镜 |
| 平板支撑 | 前臂改为朝头部一侧；肘移到肩下；肩、髋、踝连成直线，脚尖支撑 | 低机位侧面，全身入镜 |
| 俯卧撑 | 手掌改为朝头部一侧；肩、肘、腕上下对齐，修正脚尖方向 | 低机位侧面，全身入镜 |
| 卧推 | 改为推起姿态，肩、肘、腕对齐；重量位于胸肩上方，背部有凳面支撑、双脚着地 | 凳侧面，避免器械遮挡肩、肘、腕 |
| 硬拉 | 手臂改为向下，重量靠近小腿；明确髋部后移、背部平直，修正脚部方向 | 侧面，全身和重量入镜 |
| 弓步蹲 | 修正前脚支撑和后脚脚尖方向，前后腿保留清楚的分腿关系 | 侧面，前后腿和双脚入镜 |
| 肩上推举 | 检查双臂、哑铃、肩部连接，无需改变姿态 | 正面，头顶留出双手活动空间 |
| 二头弯举 | 修正哑铃握柄，使手握在柄中间；上臂留在躯干旁 | 侧面或略侧面，肩、肘、腕入镜 |
| 引体向上 | 双手接到单杠；腿部收拢、双脚离地，移除容易被误读为踩地的地面线 | 正面，单杠、双手、肩肘入镜 |

依据：ACE 的[前臂平板支撑](https://www.acefitness.org/resources/everyone/exercise-library/32/front-plank/)、[俯卧撑](https://www.acefitness.org/resources/pros/expert-articles/7265/perfecting-the-push-up-for-all-levels/)、[卧推](https://www.acefitness.org/resources/everyone/exercise-library/19/chest-press/)、[硬拉](https://www.acefitness.org/resources/everyone/exercise-library/6/deadlift/)、[弓步](https://www.acefitness.org/resources/everyone/exercise-library/94/forward-lunge/)及 NASM 的[引体向上](https://www.nasm.org/resource-center/exercise-library/pull-up)动作说明。拍摄方向是结合当前可观测关节和实现提出的产品建议，不代表这些方向均已通过真人识别验收。

## 2. 怎样让用户看懂摄像头朝向

目前文案已经区分侧面、正面和略侧面，但同一张图把“摄像头图标”和“人体侧视图”并排连接，容易让人误以为平板支撑应从头端拍摄。这两种信息需要分开表达。

建议下一步使用三个明确的信息层次：

1. **拍摄方向标签**：例如“推荐：侧面”“推荐：正面”；侧面明确说明左右任一侧均可，前提是相应方向通过验证。
2. **镜头中应看到的人体姿态**：继续使用本次修正的线稿，展示应入镜的关节和身体范围。
3. **单独的俯视机位小图**：用俯视人体、朝向和摄像头位置表达两者的空间关系。正面时镜头位于人脸朝向的一端，侧面时位于身体左右侧。不要让同一支箭头同时承担镜头朝向与动作方向。

实时提示应建立在实际检测能力上：关节缺失时提示退后或调整镜头，方向不合适时提示转身。只有完成方向估计和可靠性验证后，才能显示“当前侧面／角度合适”等检测结论。只写静态文案不能证明当前角度被识别。

## 3. 当前代码实际上支持到哪里

以下为本次直接检查的源码事实，不是根据模型名称推测：

- `desktop/src/media/pose.worker.ts` 只转发 `result.landmarks[0]`，尚未把 `worldLandmarks` 传入动作分析。
- `desktop/src/core/engine.ts` 的 `angle()` 使用归一化图像坐标 x/y/z，继承现有阈值约定。它不是基于米制世界坐标的关节角；x、y 的归一化尺度也分别依赖画面宽高，不能直接视为视角无关的真实关节角。
- `poseSelection()` 与 `session.ts` 会根据关节可见度选择身体左侧或右侧，并在一次动作内保持同一侧。这是已有基础，但“选择身体哪一侧”不等于“识别当前拍摄方向”。
- `desktop/src/core/pose-checks.ts` 的 `SquatPreparation` 用肩、髋的画面宽度比例粗略检查侧身，再要求站直、稳定后进入训练；正面深蹲目前会被这项准备检查挡住。它是启发式检查，不是精确朝向角度测量。
- 其他动作没有同等的通用方向检查。能够输出骨架，并不能证明计数与纠错在该视角可靠。
- 平板支撑的 `PlankTracker` 在肩—髋—踝夹角达到 160° 时累积时间。当前必要关节和计时条件没有充分约束肘／前臂支撑、身体水平等姿态条件，因此存在站直等非平板姿态满足主要几何条件的风险。这是源码推导的风险，本次没有进行真人复现。
- 部分纠错依赖画面投影，例如膝盖与脚踝的横向宽度比例、手腕高低差、躯干倾斜。转动摄像头会改变可观测性，不能在所有视角无差别启用这些规则。

MediaPipe 官方区分归一化图像坐标与以米计的世界坐标，并提供关节可见度。可将世界坐标作为多角度研究的候选输入，但单目估计仍受遮挡和深度歧义影响，不能仅替换坐标或改用更大模型就宣称多角度准确。参见 [Pose Landmarker 输出定义](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/python)与[模型说明](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker)。

## 4. 多角度支持的建议

赞成支持多个拍摄方向，产品应降低摆放摄像头的负担。但应按动作、视角和可观测指标逐步开放，不宜直接取消所有站位限制。

**先完成可靠的推荐视角。** 深蹲和平板支撑优先左右侧面，并验证小幅偏转的容忍范围；推举和引体向上优先正面；其他动作依照上表逐一验证。同时补平板的姿态准备条件，避免错误姿态也开始计时。

**再开放经验证的替代视角。** 增加方向估计与置信度，针对每个动作建立“允许计数／允许计时／可用纠错项”的视角表。正面深蹲更容易观察双侧对称和膝部横向关系，侧面更容易观察屈膝、髋部折叠和躯干变化；这些是可观测性差异，不能据此直接承诺识别精度。

计数和姿态评价应分开：某角度可稳定计数时可以允许计数，同时停用看不清的纠错项，并说明需要何种角度才能评估。证据不足时提示调整位置，不把遮挡当作动作错误扣分。动作进行中转身应暂停未完成动作的判断、重新稳定跟踪，保留已完成次数。

技术验证可比较：现有图像坐标、考虑宽高比例的平面角度、世界坐标角度。三者须使用同一批标注视频比较，并分别校准阈值；不要直接套用现有 165° 等阈值。前后视角、严重遮挡和不同器械环境应作为独立能力验证，不默认等同于正面或侧面。
