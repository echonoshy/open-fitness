# 语音鲁棒性修复与验证

日期：2026-10-27。对象：viaim Coach 0.3.13工作区。原检视中的F1–F7已修复，并补充了转述语句的意图约束。源码构建成功；未重新打包或替换用户当前安装、运行中的应用。

## 修复结果

| 原问题 | 修复后的行为 | 保留的边界 |
| --- | --- | --- |
| F1 正确状态回答被过滤 | 根据实际快照、工具回执和查询结果校验，“已完成6次”“摄像头已开启”可以正常回答 | 无依据的操作成功声明、错误完成次数、协议泄漏仍被拦截；没有移除原校验 |
| F2 健康关键词误暂停 | 否定、假设、知识咨询、第三人和已结束的不适描述不会仅因关键词本地暂停 | 当前明确的不适仍有及时暂停路径；本项验证意图处理，不评价医疗建议质量 |
| F3 少说话、静音和纠错混淆 | 新增set_guidance和speech_control两个模型工具；完整短句也可本地执行 | 提醒密度、临时停止、长期静音、动作纠错、麦克风相互区分 |
| F4 复合请求答案丢失 | 将真实回执与通过校验的最终答案合并，去除完全重复的回执片段；操作后no_action可正常进入回答 | 查询结果和用户另问的问题继续回答；失败工具不能被说成成功 |
| F5 停止同义词依赖LLM在线 | 完整的停止/停下来/先停一下等本地暂停；不做了/不练了/结束训练等本地结束保存 | 仅匹配完整明确的短句；否定、转述、条件、对象不同和复合请求仍交给模型，不做包含“停”就执行的匹配 |
| F6 打断后旧操作补执行 | 语音派发携带AbortSignal；摄像头等待结束、持久化排队开始及实际操作前检查取消；每轮模型请求前后检查取消 | 已完成的操作不回滚，独立按钮操作不受语音取消影响；已发起的摄像头打开本身不强制关闭 |
| F7 取消休息回执不准确 | 没有倒计时时返回“当前没有休息倒计时”；暂停中取消休息会说明训练仍暂停 | 不把取消休息偷偷变成恢复暂停训练 |

额外验证中发现“他说停下来”会被模型当成暂停，因此明确了转述与本人请求的区别。“他说停下来”不操作，“他说停下来，我也要暂停”执行暂停。两种表达均使用真实模型通过验证。

## 现在的操作语义

| 说法 | 预期并已验证的结果 |
| --- | --- |
| 停 / 停止 / 停下来 / 先停一下 | 暂停训练，保留次数 |
| 不做了 / 不练了 / 今天就到这里 / 停止训练 / 结束并保存 | 结束训练，归档并保存已完成内容 |
| 别停 / 不要停止训练 / 先别结束训练 | 不暂停、不结束 |
| 如果累了就停下来 / 等一下再停止训练 | 不立即操作 |
| 不做深蹲了，换成俯卧撑 | 切换动作，不误结束整次训练 |
| 不要结束训练，只暂停一下 | 只暂停，保留会话 |
| 停止跟随 | 固定取景，训练继续 |
| 停止说话 / 别说了 | 停止本次声音并暂缓主动播报；保留文字结果，下次实际提问恢复 |
| 关闭所有语音播报 | 保存关闭播报设置；训练、麦克风和纠错设置独立 |
| 恢复语音播报 | 恢复播报设置并解除临时停止 |
| 请少说一点 / 提醒少一点 / 不要一直鼓励我 | 主动提醒设为安静，纠错开关不变 |
| 我没有受伤，可以继续训练吗 | 不因为“受伤”二字强制暂停 |

短句本地路径在LLM不可用时仍可执行，但语音转写仍依赖ASR服务，因此这不表示完整离线语音能力。

真实服务使用桌面端已保存的配置：LLM为`deepseek-v4.1-flash`，ASR为`Qwen3-ASR-1.7B`，TTS为`voxcpm2`。请求不使用模拟LLM答案。快照、历史记录和个人资料为专用合成数据；执行的是当前生产代码中的coachTurn、SessionEngine以及从App.tsx提取的dispatch、cancel、persist、savePending函数体，只替换React、摄像头和磁盘接口。

App层另有测试直接执行当前ask函数体，验证停止说话后不继续合成回复、保留文字结果、下次请求恢复声音；取消后的迟到模型响应不写入最终答案、不播报、不执行工具。持久化队列测试验证被取消但尚未开始的设置写入不落地。

复合指令实际返回示例（初始深蹲6次、目标12次，历史样本平均分95）：

- “帮我暂停训练，然后告诉我现在做了几次” → “训练已暂停。当前深蹲完成6次，目标12次。”
- “把这组目标改成十五次，再告诉我还差几次” → 目标变为15，完成次数仍为6，最终答案包含“还差9次”。
- “暂停训练，查一下上周深蹲的平均得分” → 暂停成功，答案包含历史样本“平均动作分95分”。
- “请暂停，然后告诉我杠铃六十公斤怎么配片” → 暂停成功，答案保留“杠20公斤，每侧一片20公斤”。

## 原功能保护与验证范围

回归中检查了本组改目标不清零、新一组从零开始并保存旧组、多动作计划、平板支撑目标、参数设置、历史查询、动作知识、记忆与遗忘。训练中开启自动识别仍被拒绝并保留进度；未开始时可以开启。没有人物关键点的取景测试继续等待站稳，未强制应用2倍裁切。

第一次回归脚本将未就绪时的缩放目标当成已应用倍率，产生了测试预期错误；按原取景等待机制修正断言后单独复测通过，未改取景实现。`verified-text-final.json`保留修正说明，初轮原始结果也保留。首轮转述误暂停是真实发现，补充意图约束后扩展语义集重新验证通过。

本次没有修改用户真实训练记录、个人资料或服务配置，也没有操作正在使用的摄像头/麦克风。真实模型验证与干净合成音频验证，不等于真人远场、回声、双讲、背景音乐和真实摄像头启动的现场验收。本报告中的通过数是这组针对性样本的结果，不是统计意义上的自然语言识别准确率。

## 复核材料与复跑

- `desktop/scripts/verify-voice-robustness.ts`：可重复运行的真实服务验证脚本。

- `desktop/tests/voice-app-controls.test.ts`：生产App函数的设备等待、保存队列、播报停止/恢复和迟到响应验证。
- `desktop/tests/helpers/app-controls.ts`：提取当前生产函数体的隔离测试适配器，不复制控制逻辑。
- `desktop/output/voice-fix-20261027/summary.json`：汇总。
- `desktop/output/voice-fix-20261027/verified-text-final.json`：98条最终文字验证记录，包含原始模型输出、工具及最终状态。
- `desktop/output/voice-fix-20261027/verified-interrupt.json`、`verified-audio.json`：取消时序与合成语音结果。
- `desktop/output/voice-fix-20261027/unit-tests.log`、`build.log`：全套自动化测试及构建结果。

在desktop目录复跑：

```sh
npm test
npm run build
./node_modules/.bin/tsx scripts/verify-voice-robustness.ts "$HOME/Library/Application Support/Viaim Coach/services.json"
```

真实服务脚本可增加`--group=semantic`、`--group=regression`、`--group=interrupt`或`--group=audio`选择范围；文字组可用`--match=正则表达式`做定点复测。脚本明确读取指定服务配置，但不将凭据写入结果。
