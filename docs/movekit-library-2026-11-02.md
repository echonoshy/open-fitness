## 设计

沿用应用的 `#1e1e1e` 背景、`#262626` 面板、`#303030` 控件、`#ededed` 正文和 `#d2ed9e` 选中状态。使用现有系统字体与苹方，动作标题 15px，辅助信息 12px。视觉重点是保留全身的浅底动作封面，按窗口宽度排为四、三、两列；文字左对齐。大画面演示保留源视频比例。

```text
动作库                                     582 个图解动作
动作图解  /  训练知识  /  杠铃配片
搜索动作、器械、肌群                        可实时训练 9
器械筛选                                    动作数量
难度分类：全部 / 入门 / 进阶 / 高阶
训练肌群：全部 / 胸部 / 背部 / 肩部 / ……
[ 完整动作封面 ][ 完整动作封面 ][ 完整动作封面 ][ 完整动作封面 ]
  动作名称        动作名称        动作名称        动作名称
  肌群 / 器械     肌群 / 器械     肌群 / 器械     肌群 / 器械
```

封面延迟加载，视频只在打开详情时加载；一次仅播放一个视频。关闭弹窗、切换动作或隐藏页面时停止播放。视频失败时保留封面与重试入口；尊重系统减少动态效果偏好。原生 dialog 提供焦点限制和 Escape 关闭，关闭后焦点回到原动作卡片。

动作库内的「查看来源」和详情来源外链均已移除，保留纯文本素材来源。难度与肌群分类始终可见，可与器械和搜索组合使用；主要、辅助肌群均可被筛选和搜索。所有动作卡片显示难度，包括九个可训练动作。详情同时展示视频、主要与辅助肌群、器械、难度、中文介绍及 4–6 条动作要领；窄屏上下排列。

中文介绍与要领在 `data/movekit-library.instructions.zh-CN.json` 中按 slug 静态存储，由原动作逐条说明整理并校对，应用运行时无需模型请求。`desktop/scripts/localize-movement-instructions.py` 仅用于重新生成草稿，重跑后需要编辑校对再使用。构建会拒绝缺少介绍或要领的动作。

`data/movekit-library.zh-CN.json` 的 `classifications` 保存已核对的分类修正，避免直接改动原始来源记录。已修正杠铃硬拉和自重髋铰链被误归为斜方肌/核心的主要肌群，依据动作发力模式及 [NASM 硬拉说明](https://www.nasm.org/resource-center/exercise-library/barbell-deadlift)。

## 720p 增强处理与交付（0.3.34）

用户已选择将完整 582 条 360p 无水印素材增强到 720p。使用官方 Real-ESRGAN `realesr-animevideov3` 权重，转为 Core ML FP16，以 65% 超分结果和 35% Lanczos 原图放大混合，缓和过度平滑。原模型的 4 倍像素重排后按 2×2 面积缩小，等价折叠到最终卷积层后直接生成 2 倍结果。4 帧批处理与单帧推理的对照结果像素一致。模型只用于离线处理，不随应用运行或发起远程模型请求。

增强产物和逐条校验在 `output/movement-library-player-hd-20261102/hd/`。`promote-hd.py` 已核验 582 条输出的高度、帧数、标称帧率、时长、每帧呈现时间戳及源/输出哈希，复制至 `desktop/public/movekit-library/hd/` 并生成 `manifest.json`。构建依据清单选用增强文件，保留 360p 原文件；如果源文件更新导致 SHA-256 不匹配，构建会要求重新增强。详情中的「720p 增强」标识明确区分增强产物与原生高清素材。

- 全部 582 条、127,538 帧处理完成并完整解码通过，输出高度均为 720 像素，视频总计约 432.1 MB。源和输出的全部呈现时间戳按有理数逐帧比对一致。
- 4 条原片采用可变帧率：上斜哑铃锤式弯举、弹力带髋外展、站姿器械提踵、绳索单臂反握划船。增强后用无损重封装恢复原始时间戳，逐帧解码哈希保持不变；避免按标称帧率播放导致动作加速。容器时长最大舍入差为 8 微秒。
- 输出明确标记 BT.709 原色/传递特性与 BT.601 YUV 矩阵，避免播放器仅按 720p 分辨率猜测色彩矩阵。颜色标签通过无损重封装补充。
