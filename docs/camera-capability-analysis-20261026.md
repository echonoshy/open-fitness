# viaim Connect 摄像头能力与人物跟随分析 · 2026-10-26

本轮仅检查与临时采集测试，未修改 App 源码、安装包或固件。未采集音频。分析脚本和少量本地静态样本位于 /tmp/viaim-camera-audit-20261026，脱敏测量结果位于 output/camera-audit-20261026。

## 当前画面为何是 720p

`desktop/src/media/camera.ts` 的 getUserMedia 主动请求 width ideal 1280、height ideal 720、frameRate ideal 30。0.3.9 的 1–2 倍功能只对显示做 CSS 缩放，不改变采集分辨率。720p 画面 2 倍中心裁切仅剩约 640×360 源像素；4K 做 2 倍中心裁切则有 1920×1080 源像素。

## 多通道核验

- ADB/sysfs：RK3576 / Buildroot，传感器 subdevice 为 m00_b_imx415 4-001a。Sony 官方 IMX415 参数为约 846 万有效像素、3864×2192。
- UVC MJPEG 声明 640×480、1280×720、1920×1080、2560×1440、2592×1944、3840×2160，帧间隔 333333（约30 FPS）。
- macOS 原生 AVCaptureDevice 格式枚举独立确认上述输出档位，420v 格式约30 FPS；某些非压缩像素格式只声明5 FPS，应避免直接把不同编码格式的帧率混为一谈。
- FFmpeg/AVFoundation 初次 4K 实际采集228帧/7.99秒，约28.5 FPS。后续连续模式切换出现无帧/超时，ADB shell 同时无响应；USB重新插拔未恢复，用户将设备断电重启后恢复。未确定根因，不能直接归因于4K或断言硬件损坏。
- 重启后 Electron 使用 exact 尺寸、resizeMode none、video only，在720p/1080p/4K/2592×1944下均得到真实尺寸视频和真实帧回调，已保存并人工查看4K和4:3静态样本，不是仅根据getSettings判断成功。

| 实际输入 | 每档计时 | 帧数 | 实际显示回调 FPS |
| --- | --- | --- | --- |
| 1280×720 | 6秒 | 172 | 28.7 |
| 1920×1080 | 6秒 | 179 | 29.8 |
| 3840×2160 | 6秒 | 176 | 29.3 |
| 2592×1944 | 6秒 | 174 | 29.0 |

这是短时采集测试，不含持续训练及所有模型/语音工作负载，不代表长时间稳定性、光学分辨率或端到端运动延迟已验收。设备 current_speed=high-speed、maximum_speed=super-speed，当前USB链路不是SuperSpeed；需压缩传输4K，不能把host侧解码后的原始格式当成USB总线实际传输格式。


### 追加复开与后台采集验证

一次30秒 requestVideoFrameCallback 测试得到0次回调，但窗口已处于hidden，ADB正常且视频尺寸为3840×2160；此记录不能作为设备掉帧证据，未纳入采集帧率结论。

改用 MediaStreamTrackProcessor 直接读取源帧，避免依赖前台渲染：4K约30.1秒取得879帧，每帧尺寸3840×2160，时间戳跨度29.7082秒，源帧率约29.55 FPS；95%帧间隔62.6ms，最长98.6ms，轨道未静音。随后重新打开1080p取得156帧，源帧率约28.73 FPS。说明重启后4K和复开可用，但存在帧间隔波动，仍需分钟级及完整训练负载测试。

## 推理开销小样本

同一张4K静态真实画面，分别缩为720p、1080p或保留4K，使用应用现有Full CPU Worker，每档5次预热+30次测量，均输出33关键点。测得模型调用均值约30.5/29.0/37.9ms；包括创建bitmap和Worker往返的均值约30.7/29.4/39.1ms。顺序测量、单张近景样本，只说明4K预处理有额外开销，不证明1080p比720p稳定更快，也不证明真人计数质量一致。

Google官方说明Full的检测模型张量为224×224，关键点模型为256×256；高分辨率来源对显示/裁切很有价值，没必要把每个完整4K帧不经降采样直接交给姿态推理。建议将高分辨率显示与推理分支分开，最终以实际动作与长时间负载验证选择推理输入。

## 人物跟随可行方案

摄像头固定，通过软件移动裁切框实现电子云台(ePTZ)和自动构图。全景用于识别并计算目标中心/包围框；高分辨率原图用于提取显示区域。4K中裁切1920×1080可获得1080p输出及左右移动空间，但不能超出镜头原始视野；输出全景时没有左右平移余量。

健身场景应以躯干中心和动作所需全身关键点为依据，保留头/手/脚活动余量。增加小幅动作不跟随的稳定区域、位置平滑和速度限制；丢失目标先保留再退回全景；多人时需要目标锁定，不能依赖当前numPoses=1保证始终跟同一个人。骨架与视频使用同一裁切变换，计数维持原始坐标，不把显示镜头运动加入动作判断。

建议顺序：可靠高分辨率采集与掉帧恢复 → 手动左右构图验证坐标 → 单人自动跟随 → 多人锁定与各动作验证。本轮尚未实施任何产品功能。
